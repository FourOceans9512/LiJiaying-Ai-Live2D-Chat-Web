> 本文件是 AI Agent 在本项目中的工作准则，每次代码操作时必须遵守。  
> 详细项目规格参见 [项目规格说明书.md](../../项目规格说明书.md)。

## 0. Agent 宪法

基于参考仓库 (https://gitee.com/sliver-ring_admin/skills) 中的 AGENTS.md 和 AI_USAGE.md 模板定制，不复制粘贴。

### 0.1 宪法优先级

```
安全合规 > 角色一致性 > 帮助用户 > 诚实 > 其他
```

### 0.2 行为红线（不可违反）

| 红线 | 规则 |
|------|------|
| 违法内容 | 禁止生成暴力、色情、毒品、恐怖主义等违法内容 |
| 自残/自杀防护 | 禁止相关讨论，检测到时提供求助热线 |
| 隐私保护 | 禁止泄露用户隐私（地址/电话/身份证等），检测到时提醒用户 |
| 政治敏感 | 禁止讨论或保持中立，用户可在角色设定中自定义开关 |

### 0.3 开发工作准则

- 编码前先查相关 skill、制定计划、再动手
- 遵循 TDD：先写测试、再实现、再验证
- 系统化调试：假设 → 插桩 → 复现 → 分析 → 修复 → 验证
- 完成前必须验证（verification-before-completion）
- 所有 PR 需通过 CI (lint + test) + Code Review

## 2. 架构规范

### 2.1 整体架构

```
前端 (React + Vite, 静态托管)
  ↕ HTTPS API
后端 (Node.js + Fastify, Docker)
  → LLM / TTS / ASR (外部服务)
```

### 2.2 数据流

```
用户输入 (文本/语音)
  → 后端 API Gateway (密钥代理 + 内容安全中间件)
  → 组装 System Prompt + 上下文 → 调用 LLM
  → LLM 返回结构化 JSON: { emotion, action, expression, text, tool_calls }
  → 后端内容安全后置检查
  → (可选) 调用火山 TTS 合成语音
  → 返回前端
  → 前端解析: 显示文本 + 触发 Live2D 动作/表情 + 播放音频 + 口型同步
  → 持久化: IndexedDB (前端) + SQLite (后端)
```

### 2.3 LLM 对话结构（固定契约）

LLM 必须返回以下 JSON 结构：

```typescript
interface LLMResponse {
  emotion: string;      // happy/sad/angry/surprised/neutral/shy 等
  action: string;       // greeting/wave/nod/shake/head_tilt 等
  expression: string;   // smile/frown/surprise/blush 等
  text: string;         // 回复文本
  tool_calls?: array;   // Function Calling 结果
}
```

**任何修改此结构的改动必须同步更新前后端。**

### 2.4 口型同步实现

```
TTS 音频播放
  → Web Audio API AnalyserNode 实时分析音量
  → 计算音量包络 (RMS)
  → 映射到 Live2D ParamMouthOpenY 参数 (0.0 ~ 1.0)
  → 每帧更新 Live2D 模型参数
```

## 3. 代码规范

### 3.1 TypeScript 规则

- `strict: true`，禁止使用 `any`（除非有明确注释说明原因）
- 优先使用 `interface` 定义对象形状，`type` 用于联合类型和工具类型
- 所有 API 请求/响应使用 Zod schema 验证
- 前后端共享的类型定义放在 `packages/shared/` 或 `shared/` 目录

### 3.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件 | 组件 PascalCase，工具 camelCase，常量 UPPER_SNAKE | `ChatPanel.tsx`, `httpClient.ts`, `constants.ts` |
| 变量/函数 | camelCase | `sendMessage`, `isLoading` |
| 组件 | PascalCase | `ChatPanel`, `Live2DCanvas` |
| 类型/接口 | PascalCase | `LLMResponse`, `Character` |
| 常量 | UPPER_SNAKE_CASE | `MAX_CONTEXT_LENGTH` |
| CSS 类 | Tailwind 优先，自定义类用 kebab-case | `chat-container` |
| 环境变量 | UPPER_SNAKE_CASE，以 `VITE_` (前端) / 无前缀 (后端) | `VITE_API_URL`, `VOLC_TTS_KEY` |

### 3.4 Git 规范

```

```

#### 提交规范 (Conventional Commits)


示例：
- `feat(frontend): 实现聊天消息列表组件`
- `fix(llm): 修复 DeepSeek API 兼容性问题`

## 4. 数据规范

### 4.1 存储原则

**核心原则: 尽可能本地化存储，数据不上传到任何服务器。**

| 数据类型 | 存储 | 说明 |
|----------|------|------|
| 聊天记录 | IndexedDB (主) + SQLite (备份) | 双写同步 |
| 用户配置 | IndexedDB | 角色设定、模型配置、UI 偏好 |
| 模型元数据 | SQLite | API 地址、密钥（AES-256 加密） |
| Live2D 模型 | 浏览器 Cache API / OPFS | 大文件缓存 |
| 上传资源 | 后端本地文件系统 | 用户上传的模型、图片 |

### 4.2 密钥安全

- API Key 不暴露给浏览器，所有外部 API 调用经后端代理
- SQLite 中密钥字段使用 AES-256 加密
- `.env` 文件不提交到 Git (`.gitignore` 必须包含)
- 前端环境变量仅存非敏感配置 (以 `VITE_` 前缀)

## 5. LLM 集成规范

### 5.1 统一接口

所有 LLM 调用统一使用 OpenAI 兼容格式。非兼容厂商通过适配器转换：

```typescript
interface LLMAdapter {
  name: string;
  chat(messages: Message[], config: LLMConfig): Promise<LLMResponse>;
  listModels(): Promise<string[]>;
}
```

### 5.2 模型切换

- 用户在设置页手动选择当前 LLM
- 切换时保留对话上下文
- 每个模型独立配置: API 地址 / API Key / 模型名 / 上下文窗口

### 5.3 上下文策略

- 上下文窗口根据模型能力或用户自定义
- 超长对话: 第一版截断早期消息（保留最近 N 条）
- 长期记忆 (P2): 向量记忆 RAG，后期实现

### 5.4 System Prompt 结构

```
[角色人格设定] → 名字、性格、语气、身份背景、口头禅
[行为边界]     → 4 项红线规则
[输出格式]     → 必须返回结构化 JSON
[对话上下文]   → 最近 N 轮对话历史
```

## 6. 内容安全规范

### 6.1 后端中间件

- API Gateway 层增加关键词过滤中间件
- 词表可配置 (存 SQLite settings 表)
- 对 LLM 输出做后置检查（不对用户输入做强制过滤）
- 命中红线时拦截并返回预设安全回复

### 6.2 降级方案

| 故障 | 降级 |
|------|------|
| LLM 不可用 | 切换本地模型 (Ollama) → 预设回复兜底 |
| TTS 不可用 | 纯文字回复 |
| ASR 不可用 | 纯文本输入 |
| Live2D 加载失败 | 静态头像 + 纯聊天界面 |
| 后端不可用 | 前端直连 LLM API (降级模式) |
